# Oddroof Android UI audit: 20 Oct 2026

The audit behind the v1.20 consistency pass. It was traced through the code, file by file. The voice assistant (`ui/agent/*`) is out of scope: it renders under its own dark tokens (`VoiceOverlay.kt` provides `HqDarkColors`), so light-palette changes do not reach it.

## What was actually wrong

| # | Reported symptom | Root cause | Priority |
|---|---|---|---|
| 1 | The floating + covers content | The shell's `QuickAddFab` (56dp + 14dp inset) floats over every tab, but lists only reserved 24dp at the bottom. It also stayed visible with the keyboard open and over the full-screen Add expense / Add bill forms, which render inside the Manage tab. | P0 |
| 2 | Bills repeats itself | "Add bill" appeared up to 3 times: an inline button, a floating button, and the empty state, on top of the shell menu. "Who pays this month" was both a chip label and a section heading, and the section showed only `firstOrNull` bill. The "Upcoming" heading was gated on all bills, not active ones. | P0 |
| 3 | Bill looks paid before it is | Starting a month writes `paidBy` = this month's payer, so the rows read "Paid by X" while the status is still "Shares ready". | P0 |
| 4 | Bill started twice | "Start this month's bills" had no guard: `generateBill` never checks `lastGeneratedMonth`, and a double tap made two instances and moved the rotation twice. | P0 |
| 5 | Tasks render twice | No list renders twice. The look comes from a "Your tasks / All tasks" heading stacked right above the same My/All tabs, with the empty state and the away card shown together. | P1 |
| 6 | Same picture on every listing | Photos load correctly when they exist. A listing with no photo always fell back to one `HqArt.Home`, and the detail hero always used `home_hero`. | P0 |
| 7 | "Who lives here" repeats | It renders once. The member count, area and safety copy are repeated in nearby blocks (trust line, compatibility block, three safety notes). | P1 |
| 8 | Filters | No min > max check. Furnished, AC and WiFi were duplicated in Lifestyle. A hidden availability filter counted toward the badge. Changes applied live, so Apply did nothing and there was no cancel. Filter state used `remember`, so it was lost on rotation. | P1 |
| 9 | Placeholder data shown as real | "Not listed", "Not set", "Ask", "unknown", and a developer note on the flatmate profile. | P1 |
| 10 | Loading vs empty | Tasks, Expenses, Bills and Saved show "No … yet" before data arrives, and a failed load looks the same as empty. | P1 |
| 11 | Inconsistent spacing / shapes | 38 literal `RoundedCornerShape(n.dp)`, 4 raw colours, odd paddings (3/7/11/13/15/18/23 dp), a 29sp one-off heading, a 16dp gutter on Bills against 20dp everywhere else. | P2 |

## Plan (as executed)

1. **Shared:** add `HqSpacing.fabClearance` and `HideShellChrome()`, and hide the + while the keyboard is open.
2. **Tokens:** align the light palette to the brief wherever contrast allows. Radii: controls 12, cards 16, sheets 24; buttons are no longer pills.
3. **Manage:** de-duplicate Bills, guard bill generation, fix the "paid" wording, add loading/error before empty, tidy the Tasks heading, apply fabClearance.
4. **Discover:** per-listing placeholder art, a filter draft with Apply/Reset and validation, de-duplicated detail sections, hide empty facts, saved-flat heart toggle, fabClearance.
5. **Profile / Members:** a grouped member list, no placeholder values, confirmation on Log out and Decline.
6. **QA:** compile, run all unit and screenshot tests, build the APK.

## Deviations and leftovers (v1.20)

- **Contrast changes from the brief:** four brief colours failed 4.5:1, so the closest passing value on the same hue is used instead. These are muted text #656F7F, disabled text #616C7C, success #207E56 and warning #9E6411. As a result, muted, secondary and disabled text now look nearly the same.
- **Raw Material kept:** the filter sheet is still a raw `ModalBottomSheet`, because `HqBottomSheet` has no header slot or sticky footer. The Report sheet and the trust "Why?" popup still use `AlertDialog`. Both need a richer Hq overlay component.
- **Saved paused listings:** a saved flat whose listing is paused is hidden from Saved, not deleted. It comes back if the listing is re-activated.
- **Invite code:** the invite code is still the flat document id. This is separate security work (see the 18 Oct security audit).
- **Not yet checked on a real device:** keyboard insets in the filter sheet, the hero text contrast over the photo, and the new placeholder art.

## Preserved

All repositories, Firestore writes, split and settlement maths, roles and permissions, the IA (Home · Manage · mic · Discover · Profile), and the voice assistant's visuals.
